真人用户动态评测方案（RealUser）

在动态评测阶段由真人扮演用户，侧栏展示完整意图指针序列；评审与意图切换由操作员手动完成（按钮），仅被测 Agent 走 LLM。 与 LLM 融合方案 并列，可作为回归测试的「高保真人工臂」。

紫 · 真人用户臂 蓝 · 被测 Agent（LLM） 绿 · 共用资产 / Zeval 指标

一、定位与核心价值

目标说明
降本 去掉动态环内的「模拟用户 LLM」与「评审 LLM」，单轮仅调用被测 Agent，Token 与延迟显著下降。
意图精准 操作员对照完整意图表切换指针、自行发问，避免 SimUser 漂移或 Judge 误判带来的指针推进错误。
真人体感 回归测试除自动指标外，可记录操作员主观打分（顺畅度、信任感、是否愿继续用等），补足纯 LLM 评测盲区。
可参与 产品、标注、领域专家可进入「真实动态评测」过程，形成可讨论的评测记录而非仅看终局分数。

二、与 LLM 融合方案对比

维度LLM 融合动态评测真人用户动态评测（本方案）
用户侧 模拟用户（LLM 生成话术） 真人输入（键盘/话术参考示例句）
评审 评审模型三分类 + 细项 人工点选：满足 / 未满足 / 偏离
意图指针 程序按评审自动推进（有预算上限） 人工切换当前指针（可强制跳过/重试）
意图可见性 模拟用户仅看当前意图（融合后） 侧栏展示完整序列（达成标准、示例话、依赖关系）
可回填项 按意图注入被测 Agent 同左（仍只给 Agent，不给真人侧「泄题」除非设计为操作员参考卡）
规模化 适合批量、夜间跑分 人力密集，适合抽检、关键版本、争议 case
一致性 依赖模型与 prompt 版本 依赖操作员培训与 SOP，但评审更贴近业务直觉

六、操作员控件清单

控件作用
当前意图高亮侧栏展示完整序列，仅高亮正在测的意图
上一意图 / 下一意图手动切换指针（可配 SOP：未满足是否允许跳过）
评审：满足 / 未满足 / 偏离替代 LLM Judge，写入与融合方案相同三分类
确认本轮回合落库一轮日志（用户话、Agent 话、评审、时间戳、操作员 ID）
真人体感打分可选：顺畅度、可信度、是否愿继续（1–5 或 Likert）
备注记录歧义、产品直觉，供报告引用
结束并导出生成与 LLM 臂格式兼容的 TXT/JSON，便于对比

七、指标：自动 + 真人体感

类型指标（中文）来源
自动（与融合共用）意图完成率、偏离率、轮次效率、会话深度、结果交付率等由人工评审标签聚合，算法同 LLM 臂
真人体感（新增）操作顺畅度、回复可信度、愿继续对话意愿每轮或每意图结束时人工打分
真人体感（可选）整体会话满意度、是否推荐上线、主观「像真人客服」程度会话结束问卷
过程质控操作员间一致性、单会话耗时、跳过意图次数平台审计字段

说明：共情曲线、响应间隔等仍建议只从基线 B（历史真实对话）计算；动态真人臂的「情绪」来自操作员，不宜直接套原 chatlog 情绪模型。

八、适用场景与难点

适合

  • 发版前关键 Session 抽检、新 Agent 版本对比
  • LLM 臂与历史真人体验差异大时的仲裁
  • 需要向业务方演示「可参与」的评测过程

难点

人力成本：无法替代大批量夜间回归，宜与 LLM 臂组合使用。
操作员偏差：需 SOP、双盲或抽样复核，避免「一律点满足」。
完整意图表可见：真人已知全局目标，与被测 Agent「仅局部回填」不对称——需在报告中标注评测臂=真人全览，与生产用户信息不对称。
双轨指标：同一 Session 的 LLM 臂与真人臂分数不可简单平均，看板应分开展示。

九、实施要点（POC 可落地）

  • 在 eval-test-v1 增加模式开关：全自动动态评测 / 真人操作台
  • 真人模式：左侧只读意图表 + 右侧控制栏；对话区复用现有气泡组件
  • 日志结构扩展：judge_source=human、operator_id、human_scores
  • 导出格式与融合方案对齐，便于同图对比 B / D-LLM / D-真人
