真人用户臂 被测 Agent 共用会话资产

一、方案定位

目标说明
降低 LLM 用量真人替代 SimUser 和 Judge，动态环内只调用被测 Agent。
保证意图精准真人直接查看完整意图指针序列，手动切换意图并点选 Judge 状态。
加入体感维度每轮记录顺畅度、可信度、愿继续对话意愿，补充自动指标看不到的体验问题。
用于抽检与争议复核不替代大批量自动回归；适合关键版本、重点 session 和可疑 badcase。

二、界面与流程

真人模式：左侧看意图，中间真实对话，右侧人工评审与体感记录。

三、当前 POC 实现口径

项目当前实现
Agent 调用复用现有 SiliconFlow 设置，仅调用被测 Agent。
指针推进点“满足”并确认后自动进入下一意图；仍可手动上一/下一意图。
可回填展示操作台折叠展示当前意图相关可回填项摘要。
体感分每轮记录顺畅度、可信度、愿继续，范围 1-5。
导出导出真人评测 TXT，包含抽取结果、对话、人工 Judge 与体感分。

四、问题与修复记录

日期问题原因修复 / 方案状态
2026-05-25 动态评测首条用户问题不稳定，容易导致开场意图漂移。 抽取模型可能改写 example_user_queries；动态环若直接用抽取结果，首轮并不一定等于历史真实 user 话。 抽取后根据 historical_span 回填该 span 内第一条真实 user 话；自动动态评测运行时也优先从 sessions.json 原始 span 读取首条 user query。 已修复
2026-05-25 同一 session 重复抽取结果不复现，意图和可回填项会变化。 原逻辑每次点“运行抽取”都会重新调用 LLM；historical_span 和 refillables 都由 LLM 一次性判断。 首次抽取后立即绑定到该 session（复用 data/locked/{session}.json）；后续抽取优先读取绑定结果。UI 文案改为“抽取/读取绑定结果”。 已修复
2026-05-25 意图片段边界模糊。 当前抽取方式是将完整 session + CSV_AUX 一次性输入 LLM，由 LLM 输出完整意图链与每个 historical_span；schema 只校验结构，不校验边界合理性。 短期：绑定抽取结果并固定首轮 query，降低波动。后续建议：对 MultiWOZ 类数据先用 active_intents / slot_values 规则生成候选 span，再让 LLM 做命名、达成标准和可回填补充。 待增强
2026-05-25 被测 Agent 编造新餐厅，未复用历史事实或可回填项。 抽取阶段可能漏掉餐厅名、电话、确认号等事实；动态评测如果只注入可回填项，Agent 仍会自由发挥。 自动模式与 RealUser 模式都改为注入“当前意图历史片段 + 当前意图相关可回填项”，作为仅对 Agent 可见的内部事实，减少编造。 已修复
2026-05-25 字段名偏工程化，真人操作员不易理解。 表格沿用 schema 字段，如 intent_index、success_criteria。 表格表头改为中文：意图序号、意图文本、示例用户话、达成标准、依赖意图、历史起止轮、回填序号、注入文本等。 已修复

五、后续建议

最关键改造：不要长期依赖 LLM 自己决定意图片段边界。对于带 active_intents 和 slot_values 的数据，应先规则生成候选片段，再交给 LLM 完成语义整理。
  • 为绑定抽取结果增加独立目录或表名，例如 data/session-assets/，避免继续借用 locked 概念。
  • 导出时同时附带：原始历史片段、当前意图可回填项、实际注入给 Agent 的内部事实，便于排查漂移。
  • 为真人模式加入操作员 ID、确认时间、是否手动跳指针等审计字段。
