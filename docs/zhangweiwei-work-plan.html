四、模块一：Rubric 评分表单与区分度优化

会议结论：从 yes/no 改回 1 / 3 / 5 最多五档；每档需配 fewshot 案例；首轮指标不能只有 3 个；无金标禁用会虚高的 exact_match；评测失败应阻塞（与 Roger 对齐）。

当前代码痛点（你已定位） evaluators.ts 规则评测器二值化；exact_match 空 expected 给满分；copilot.ts 兜底只出 3 指标；generic-run 对「二次 JSON 分析」再评测（嵌套一层）；置信度 ~0.98 黑盒。

五、模块二：Good Case ReRank

会议共识：认可入池的 good case 不能扁平；在池内按二级指标加权分做排序，前 25% = top good（gold），中间 silver，尾部 borderline。需同时保留单维度特征供按某一指标纵向比较。

5.1 标准化公式（回应会议「横评」问题）

不同一级指标下的二级指标要合成一个 Q 分，同时保留单向量供单指标排序：

// case 级综合质量分
Q = Σ_metric ( w_cap(cap) · w_metric · norm(score) · confidence )
    − λ₁ · judgeVariancePenalty      // Roger 三模型方差大则扣分
    − λ₂ · metricDisagreementPenalty // 指标间分歧大则扣分

// 单指标纵向比较（按 task_success 排 goodcase 时）
rankByMetric(m) = sort cases by norm(score_m) descending

六、模块三：静态入池 Policy 规则引擎

会议共识：人工标定约 100 条后，从二级指标特征学习静态 Channel Admission Policy；后续样本按规则自动建议入池；默认每批 100 条人工、其余自动（sampleRateForHuman）。讨论中提到 K-means 聚类划定特征空间 — MVP 先用分位数规则，聚类作为增强项。

六（补）、Policy 生成引擎与判定/计算标准

Policy 分两段：离线生成（PolicyLearner 从标定样本拟合规则）与在线判定（AdmissionScorer 对新样本逐条求值）。两段均为纯函数、可单测，不依赖 UI。

6.4 生成引擎（PolicyLearner）输入 / 输出

阶段输入输出
① 对齐 humanReviewRecords[] join metricResults[] on submissionId + metricKey 标定行 LabelRow：sessionId、channel、decision、autoScore、confidence、qualityScore、tier
② 分组 按 channel 切分；decision 分为 accept / reject / needs_evidence 每 channel 两个样本集：acceptSet、rejectSet（needs_evidence 不进规则学习）
③ 统计 各集合上的 score、confidence、qualityScore 数组 分位数、中位数、一致率等 ChannelStats
④ 拟合规则 ChannelStats + 全局配置（最小样本数、灰区宽度） AdmissionPolicy JSON（per-channel accept/reject/uncertainty 规则）

6.5 规则拟合公式（MVP · 分位数法）

对每个 channel，设 accept 组分数数组 A、reject 组 R（样本数均 ≥ minSamplesPerGroup，默认 8，不足则该 channel 只产出 uncertainty 规则）：

// 分位数（线性插值）
P(q, arr) = 第 q 分位点的值

// accept 规则（偏保守：取 accept 组的较低分位作为入池下限）
scoreGte       = P(0.20, A.score)          // accept 组 20% 分位
confidenceGte  = median(A.confidence)
qualityPctGte  = P(0.30, A.qualityScore) // 仅当存在 reRank 后 Q 分

// reject 规则（偏保守：取 reject 组的较高分位作为拒绝上限）
scoreLte       = P(0.80, R.score)

// 灰区 / uncertainty（两规则之间的带状区域 + 低置信）
uncertaintyRules = [
  { scoreBetween: [scoreLte, scoreGte] },   // 仅当 scoreLte < scoreGte
  { confidenceLt: confidenceGte },
  { judgeVarianceGt: 0.35 }                 // Roger 三模型方差，可选
]

// 人工抽检比例（会议 sampleRateForHuman）
agreementRate = |{ row : humanPassed(row) === autoPassed(row) }| / N
sampleRateForHuman = clamp(1 - agreementRate, 0.10, 0.50)
// 例：一致率 81% → 约 19% 仍需人工；下限 10%，上限 50%

6.6 判定引擎（AdmissionScorer）决策顺序

对一条 session × channel 特征 f，按固定优先级求值（避免规则冲突）：

scoreAdmission(f, policy[channel]) → AdmissionDecision

1. REJECT   若任一 rejectRule 命中
2. ACCEPT   否则若全部 acceptRule 命中（AND 关系）
3. HUMAN    否则若任一 uncertaintyRule 命中
4. HUMAN    默认兜底（无规则覆盖时走人工，宁可漏不可错）
规则类型字段命中条件
scoreGtef.autoScoreautoScore ≥ scoreGte
scoreLtef.autoScoreautoScore ≤ scoreLte
confidenceGtef.confidenceconfidence ≥ confidenceGte
confidenceLtf.confidenceconfidence < confidenceLt
qualityPercentileGtef.qualityPercentile在本 run passed cases 中的 Q 分百分位 ≥ 阈值
scoreBetweenf.autoScorelow ≤ autoScore ≤ high
judgeVarianceGtf.judgeVariance三模型评分离散度 > 阈值

6.8 P2 增强：K-means 辅助边界（可选）

在 accept 组特征向量上跑 K-means（K=1~3，按样本量选择），得到质心 μ 与簇内最大距离 r，追加规则：

acceptIf: euclidean(f.vector, μ) ≤ r × 1.2
否则 → uncertainty（落入 accept 点云外缘）

与分位数规则并联：分位数负责可解释阈值，K-means 负责多指标联合边界；两者任一拒绝则不进 accept。

八、总验收清单

模块一 · Rubric

  • 首轮 Rubric ≥6 指标，情绪陪伴场景覆盖共情/留存等维度
  • 每指标 rubricForm 含 fewshot example
  • 跑分输出 1/3/5 多档，非 yes/no
  • undefined / 空 expected 阻塞，不默认满分
  • transcript 模式：companion_pos 均分显著高于 companion_neg

模块二 · ReRank

  • case 级 Q 分与 rankInRun 写入 run 结果
  • gold / silver / borderline 三段划分（top 25% = gold）
  • 支持按单一二级指标重排
  • 入池候选默认带 qualityTier

模块三 · Policy

  • 100 条标定生成 admission-policy-v1.json
  • AdmissionScorer 对新样本输出 accept/reject/human 建议
  • sampleRateForHuman 可配置（默认约 1/3 人工）
  • 与 evaluate 五通道 source 映射一致
  • （P2）K-means 辅助规则可选开启

联调（与 Roger）

  • 两级标签 UI 能展示 metricVector / tier / policySuggestion
  • 三模型方差字段进入 ReRank penalty
  • 线性审阅：选一个 session → 一个指标 → 判断 → 入池 → 下一个
