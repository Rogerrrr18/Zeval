## 一、发现的问题

### 1. 评测链路逻辑混乱
- 评测流程从"依据 rubric 评分"变成了 yes/no 二元判断（通过/不通过），不符合设计预期
- 兜底流程导致评测只输出3个二级指标，流程被提前截断
- undefined 结果被默认给5分，评测失败后回退到满分，两个因素叠加导致评分全100分
- 目前评测是对"评测结果"再进行评测（嵌套了一层），逻辑需要重新梳理

### 2. MVP 数据限制
- 当前 MVP 只评测前8条 session，数据量大时大量数据被忽略
- 需确认评测上限逻辑并修正

### 3. UI 展示问题
- 所有指标全量平铺，数据多时人工校验效率低
- 需改为两级标签折叠筛选

### 4. 置信度黑盒
- 当前置信度输出均在98左右，含义不清、计算逻辑不明

### 5. 评测器单一模型问题
- 单模型评测结果不稳定，两次运行可能给出不同 rank，缺乏可复现性

---

## 二、讨论改进方案

### 1. 评测流程重构
- 兜底策略改为**阻塞**：评测失败或 undefined 时直接报错提示，不再自动兜底
- 评分从二元（yes/no）改为**多档细粒度**（1/3/5，Roger 建议最多5档，需配合 fewshot case）

### 2. 评测器升级：多模型混合评测
- 使用**3个不同模型**各跑一次，取平均分
- 计算**方差**：方差过大（三个模型评分差异大）的样本标记为异常，人工复核
- 这套方案有差异性、有可复现性，是一个小创新点

### 3. Auto 范功能（新增）
- 用户只需描述需求，系统自动抓取公开相关数据，组成20条机审样本（10正10负）
- 规避用户数据字段不完整、覆盖不均的问题
- 适用于**预实验**：多轮迭代前先用小样本验证评测指标完整性

### 4. UI 改版方向
- 改为两级标签折叠：Season ID 折叠 → 二级指标折叠，点击线性展开
- 一级标签考虑改为**下拉选择器**，应对 session 数量多的情况
- 人工校验队列放4块内容：原始会话ID折叠、总评维度、人工校校验、rerank结果

### 5. ReRank + 自动化入池路线图
- **当前问题**：所有认可结果直接入池，无区分度
- **目标**：基于二级指标加权分数做 rerank，在池内按百分比划分（前25% = top good case）
- **标准化**：不同一级指标各有权重，最终汇总总分；同时保留单维度特征用于细粒度排序
- **自动化入池规则**：人工标注达到一定量（如100条）后，聚类学习特征向量，生成静态 policy（channel admission policy），后续样本自动打标入池
- **样本率**：默认每次取100条人工评测，其余自动打标
